## 1. npm и package.json

**Концепция.** npm — менеджер пакетов. Он не часть Vue и не часть JS-языка — это отдельный
инструмент, который скачивает чужой код (библиотеки) в папку `node_modules` и запускает
команды, описанные в `package.json`.

```json
{
  "scripts": {
    "serve": "vue-cli-service serve",   // npm run serve  → запускает dev-сервер
    "build": "vue-cli-service build"    // npm run build  → собирает прод-версию
  },
  "dependencies": {
    // Нужны в браузере, ВО ВРЕМЯ работы приложения
    "vue": "^3.2.13"
  },
  "devDependencies": {
    // Нужны только при РАЗРАБОТКЕ/СБОРКЕ, в финальный билд не попадают
    "@vue/cli-service": "~5.0.0"
  }
}
```

- `npm run <имя>` — ищет ключ `<имя>` в `scripts` и выполняет то, что за ним записано.
- `^3.2.13` — можно ставить любые обновления вплоть до следующей МАЖОРНОЙ версии (`3.x.x`).
- `~5.0.0` — можно ставить только патч-обновления (`5.0.x`), более строго.
- `npm install <пакет> -D` (или `--save-dev`) — установить именно в `devDependencies`.

## 2. Точка входа — main.js

**Концепция.** Браузер не понимает `.vue`-файлы напрямую. `main.js` — это обычный JS-файл,
с которого стартует всё приложение, он "склеивает" Vue-код с реальной HTML-страницей.

```js
import { createApp } from 'vue'   // фабрика, создающая экземпляр Vue-приложения
import App from './App.vue'       // корневой компонент

createApp(App)       // создаём приложение, App — его корень
  .mount('#app')     // ищем в реальном DOM элемент с id="app" и вставляем туда всё дерево
```

```html
<!-- index.html -->
<div id="app"></div>  <!-- изначально пустой контейнер -->
```

Связь `mount('#app')` ↔ `id="app"` — **не импорт**, а совпадение строк, которое проверяется
только в момент выполнения кода в браузере. Опечатался в одной из строк — получишь белый
экран без единой ошибки в консоли.

## 3. Устройство .vue-файла (Single File Component)

**Концепция.** `.vue`-файл — специальный формат, который на этапе сборки (`vue-loader`)
разбирается на три независимые части и превращается в обычный JS-модуль.

```vue
<template>
  <!-- РАЗМЕТКА. Компилируется в функцию render() -->
</template>

<script>
export default {
  // ЛОГИКА: данные, методы, пропсы, хуки жизненного цикла
}
</script>

<style scoped>
  /* СТИЛИ. scoped — привязывает их только к этому компоненту */
</style>
```

`scoped` добавляет всем элементам этого шаблона и всем селекторам в этом `<style>` уникальный
атрибут (например `data-v-7ba5bd90`) — стили не "утекают" на другие компоненты. Без `scoped`
стили глобальные, как в обычном CSS-файле.

## 4. data() и methods

**Концепция.** `data()` — функция (**обязательно функция, не объект!**), возвращающая объект
с полями, за которыми Vue будет следить. `methods` — функции-обработчики, которые эти поля меняют.

```js
export default {
  data() {
    // Функция, а не { likes: 0 } напрямую — если бы это был просто объект,
    // все экземпляры компонента делили бы одни и те же данные между собой.
    // Функция гарантирует новый независимый объект при КАЖДОМ создании компонента.
    return {
      likes: 0,
      dislikes: 0,
    }
  },
  methods: {
    addLikes() {
      // this — реактивный прокси вокруг data(). Изменение this.likes
      // автоматически обновляет DOM везде, где likes используется в <template>.
      this.likes += 1;
    }
  }
}
```

Механизм: Vue оборачивает объект из `data()` в `Proxy` и отслеживает, какие поля читаются в
`<template>`, чтобы точечно обновлять DOM при их изменении — без полной перерисовки страницы.

## 5. computed — вычисляемые свойства

**Концепция.** `computed` — третье поле, помимо `data` и `methods`. Оно НЕ хранит своё
значение, а вычисляется из других реактивных полей и пересчитывается автоматически, но
только когда реально меняются его зависимости (кэшируется).

```js
export default {
  data() {
    return { likes: 0, dislikes: 0 }
  },
  computed: {
    // Не хранится сам по себе — вычисляется из likes и dislikes.
    // Пересчитывается САМ, когда меняется likes или dislikes, и только тогда.
    rating() {
      return this.likes - this.dislikes;
    }
  }
}
```

```html
<div>Рейтинг: {{ rating }}</div>
<!-- Обращение в template такое же, как к обычному полю из data() — без скобок () -->
```

`methods` тоже мог бы это сделать (`getRating()`), но пересчитывался бы при **каждом** рендере
компонента, даже если `likes` не менялся. `computed` кэширует результат — пересчёт только при
реальном изменении зависимостей.

## 6. watch — наблюдатель за изменениями

**Концепция.** `watch` следит за конкретным полем и запускает код, когда оно меняется.
В отличие от `computed`, `watch` не возвращает значение в шаблон — он нужен для побочных
эффектов: запрос на сервер, лог, валидация.

```js
export default {
  data() {
    return { title: '' }
  },
  watch: {
    // Вызывается каждый раз, когда title меняется.
    // newVal — новое значение, oldVal — то, что было до этого
    title(newVal, oldVal) {
      console.log(`Заголовок изменился: ${oldVal} → ${newVal}`);
    }
  }
}
```

**computed** отвечает на вопрос "что показать" (производное значение для шаблона).
**watch** отвечает на вопрос "что сделать" при изменении (действие, а не значение).
Их часто путают — при выборе спрашивай себя: мне нужно значение или действие?

## 7. Директивы шаблона — шпаргалка по синтаксису

| Директива | Полная запись | Что делает |
|---|---|---|
| `{{ }}` | — | Интерполяция: подставляет значение переменной в текст |
| `:attr` | `v-bind:attr` | Связывает HTML-атрибут или проп с переменной |
| `@event` | `v-on:event` | Вешает обработчик события |
| `v-model` | `:value` + `@input` | Двусторонняя связь поля ввода |
| `v-for` | — | Цикл по массиву/объекту |
| `v-if` / `v-show` | — | Условный рендер (два разных механизма, см. 7.6) |

### 7.1. Интерполяция

```html
<div>{{ post.title }}</div>
<!-- Аналог в чистом JS: el.textContent = post.title -->
<!-- Реактивна: меняется post.title → текст обновляется сам -->
```

### 7.2. v-bind (`:`)

```html
<img :src="imageUrl">
<!-- Аналог: el.setAttribute('src', imageUrl) -->
<!-- Разница: Vue сам обновит атрибут при изменении imageUrl -->
```

### 7.3. v-on (`@`) и модификаторы

```html
<button @click="addLikes">Likes</button>
<!-- Аналог: el.addEventListener('click', addLikes) -->

<form @submit.prevent>
<!-- .prevent — модификатор. Аналог:
     form.addEventListener('submit', e => e.preventDefault()) -->
```

Другие частые модификаторы: `.stop` (аналог `e.stopPropagation()`), `.once` (сработает один раз).

### 7.4. v-model

```html
<input v-model="post.title">
<!-- Разворачивается в ДВЕ вещи одновременно:
     :value="post.title"                          — вывести текущее значение
     @input="post.title = $event.target.value"    — записать новое значение при вводе -->
```

### 7.5. v-for

```html
<div class="post" v-for="post in posts" :key="post.id">
  {{ post.title }}
</div>
<!-- Аналог: for (const post of posts) { ... } -->
<!-- :key — уникальный id, подсказка Vue, какой DOM-узел к какому объекту массива
     относится, при добавлении/удалении элементов. Без него — предупреждение в консоли. -->
```

### 7.6. v-if / v-else / v-show

```html
<div v-if="likes > 10">Популярно!</div>
<div v-else>Пока не очень</div>
<!-- v-if — элемента ВООБЩЕ НЕТ в DOM, пока условие ложно (создаётся/удаляется целиком) -->

<div v-show="likes > 10">Популярно!</div>
<!-- v-show — элемент ВСЕГДА в DOM, просто display:none, когда условие ложно -->
```

`v-if` дороже при частом переключении (пересоздаёт DOM каждый раз), но дешевле на старте,
если условие обычно `false`. `v-show` — наоборот. Правило: часто переключается → `v-show`;
редко → `v-if`.

### 7.7. Динамические классы и стили

```html
<div :class="{ active: isActive, disabled: isDisabled }">
<!-- Класс "active" добавится, только если isActive === true -->

<div :class="[baseClass, extraClass]">
<!-- Просто объединяет строки классов из массива -->

<div :style="{ color: textColor, fontSize: size + 'px' }">
<!-- camelCase вместо kebab-case: fontSize, а не font-size -->
```

## 8. Компоненты — родитель и потомок

**Концепция.** Компонент = переиспользуемый кусок UI + логика. Родительский компонент
использует дочерний примерно так же, как обычная функция вызывает другую функцию.

### 8.1. Импорт и регистрация

```js
import PostForm from "./components/PostForm.vue"

export default {
  components: {
    PostForm   // ES6 property shorthand — сокращение для { PostForm: PostForm }
  }
}
```

### 8.2. Использование в шаблоне

```html
<post-form/>
<!-- Тег компонента — как вызов функции postForm() -->
<!-- PascalCase в JS (PostForm) = kebab-case в шаблоне (post-form). Это не два разных
     компонента, а два способа записи одного и того же имени -->
```

### 8.3. Данные "вниз" — props

```html
<!-- Родитель передаёт данные -->
<post-list :posts="posts"/>
<!-- Аналог: postList(posts) — аргумент функции -->
```

```js
// Потомок объявляет, что готов принять
export default {
  props: {
    posts: {
      type: Array,      // проверка типа
      required: true    // обязателен, иначе — предупреждение в консоли
    }
  }
}
```

## 9. $emit — данные "вверх", от потомка к родителю

**Концепция.** Проп идёт только сверху вниз (родитель → потомок). Чтобы потомок сообщил
что-то родителю (например «пользователь заполнил форму, вот данные») — используется
кастомное событие через `this.$emit('имя-события', данные)`, а родитель слушает его через
`@имя-события="обработчик"`. Именно этого не хватает в текущем `PostForm.vue`.

```js
// PostForm.vue (потомок)
export default {
  data() {
    return { post: { title: '', body: '' } }
  },
  methods: {
    submitPost() {
      // $emit генерирует кастомное событие 'create-post'
      // и передаёт объект post вторым аргументом
      this.$emit('create-post', this.post);
      this.post = { title: '', body: '' };   // очистка формы
    }
  }
}
```

```html
<!-- PostForm.vue шаблон -->
<form @submit.prevent="submitPost">
  ...
</form>
```

```html
<!-- App.vue (родитель) -->
<post-form @create-post="addPost"/>
<!-- @create-post слушает событие с ИМЕННО ТАКИМ именем, как в $emit -->
```

```js
// App.vue script
methods: {
  addPost(post) {
    // post — тот самый объект, который пришёл вторым аргументом $emit
    this.posts.push({ id: crypto.randomUUID(), ...post });
  }
}
```

## 10. Слоты — передача разметки в компонент

**Концепция.** Проп передаёт данные. Слот передаёт **разметку** — компонент оставляет
"дыру", в которую родитель может вставить любой HTML.

```html
<!-- Card.vue -->
<div class="card">
  <slot></slot>
  <!-- Сюда подставится всё, что родитель напишет между <card> и </card> -->
</div>
```

```html
<!-- Использование -->
<card>
  <h3>Заголовок</h3>
  <p>Любая разметка от родителя</p>
</card>
```

Есть ещё именованные слоты (`<slot name="header">`), когда в одном компоненте нужно
несколько "дыр" под разную разметку — это уже следующий уровень, когда дойдёшь до
многократно переиспользуемых UI-компонентов (карточки, модалки, кнопки).

## 11. Хуки жизненного цикла

**Концепция.** Хуки — специальные методы, которые Vue вызывает сам в определённые моменты
"жизни" компонента: создание, вставка в DOM, обновление, удаление.

```js
export default {
  created() {
    // Компонент создан, но DOM ЕЩЁ НЕ существует
    console.log('Компонент создан');
  },
  mounted() {
    // Компонент УЖЕ вставлен в реальный DOM.
    // Здесь можно безопасно обращаться к DOM-элементам
    console.log('Компонент в DOM');
  },
  updated() {
    // Вызывается после каждого обновления DOM из-за изменения данных
  },
  unmounted() {
    // Перед удалением компонента — здесь чистят таймеры, подписки
  }
}
```

| Хук | Когда срабатывает |
|---|---|
| `created` | Данные уже реактивны, но DOM ещё не существует |
| `mounted` | DOM готов, компонент реально на странице |
| `updated` | После каждого повторного рендера из-за смены данных |
| `unmounted` | Компонент удаляется — время убрать за собой |

## 12. ES6-фишки, которые тут повсюду (это чистый JS, не Vue)

// Property shorthand — если имя переменной совпадает с именем ключа

## 13. Что дальше — Composition API (коротко)

**Концепция.** Всё, что было выше, — Options API (`data`/`methods`/`computed`). Это то,
что используется в твоём курсе. Но у Vue 3 есть второй способ писать компоненты —
Composition API — его ждут во многих современных проектах и вакансиях. Пока не
обязательно, но полезно узнавать в лицо.

```js
// Options API (то, что было выше)
export default {
  data() { return { likes: 0 } },
  methods: { addLikes() { this.likes++ } }
}
```

```js
// Composition API (тот же смысл, другой синтаксис)
import { ref } from 'vue'

export default {
  setup() {
    const likes = ref(0)              // реактивная переменная
    function addLikes() { likes.value++ }   // .value — доступ к значению внутри script

    return { likes, addLikes }        // то, что вернули, доступно в template
  }
}
```

В `template` разница незаметна — `{{ likes }}` и `@click="addLikes"` пишутся одинаково
в обоих подходах. Разница только внутри `<script>`.

## 14. Мини-глоссарий

- **SFC (Single File Component)** — файл `.vue`, объединяющий template/script/style одного компонента.
- **Реактивность** — механизм, при котором изменение данных автоматически обновляет DOM.
- **Директива** — специальный HTML-атрибут вида `v-что-то`, который Vue обрабатывает по-своему.
- **Проп (prop)** — "входной параметр" компонента, передаётся от родителя к потомку.
- **Интерполяция** — вставка значения переменной в текст через `{{ }}`.
- **computed** — вычисляемое свойство: не хранится, а выводится из других полей, с кэшированием.
- **watch** — наблюдатель за изменением поля, для побочных эффектов (не для вывода в шаблон).
- **$emit** — способ потомка отправить кастомное событие с данными родителю.
- **Слот** — "дыра" в компоненте, куда родитель может вставить свою разметку.
- **Хук жизненного цикла** — метод, который Vue вызывает сам в определённый момент существования компонента.
- **Composition API** — альтернативный (более новый) способ писать компоненты через `setup()` и `ref()`.
- **devDependencies** — пакеты, нужные только при разработке/сборке, не идут в финальный билд.
- **kebab-case / PascalCase** — `post-form` и `PostForm` — одно и то же имя, два формата записи.
